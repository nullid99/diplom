# FireVision — оформлення інтерфейсу

## Реалізовано

Причина вузької колонки: глобальний main мав max-width 980 px і margin 40px auto; великий заголовок теми роботи повторювався над сторінками. Окремих App.css/index.css зі стилями шаблона Vite у поточному src не було. Тепер #root займає всю доступну ширину, sidebar — 240 px, header — 64 px, робочий вміст — до 1600 px, поля робочої області 32 px (24/16 на менших екранах). CSS zoom і transform:scale не застосовуються. Тема магістерської збережена в PROJECT_CONTEXT.md.

Спільний AppLayout, нативні History API / popstate маршрути з реальними href, desktop sidebar і modal drawer на малих екранах, компактний фактичний статус GET /api/health. Власні SVG-іконки, локальний favicon, спільні токени та PageHeading/Panel/EmptyState/Badge/Planned/Notice/Icon. Поточний React/TypeScript/Vite і звичайний CSS збережено; пакети не додавали. Локального Inter у проєкті не було, використано Segoe UI/system sans-serif, без Google Fonts/CDN. Основний текст 16 px, заголовки 28/26 px, панелі 18 px, поля/основні кнопки 42 px. Другорядний колір трохи затемнено до #5F6F83 для контрасту на #F5F6F8; решта основних орієнтирів палітри збережена.

| Маршрут | Що функціонально працює | Що є макетом |
| --- | --- | --- |
| /sources | Чинні multipart upload, фактичний upload/checking state, ліміт, список/пагінація лише за потреби, деталі, відео/помилки кодека | Немає нової вигаданої функціональності |
| /analysis | Чинні API/WS, параметри/start/cancel/request vs ack, збережений запуск/reconnect/reload, історія, player і файли готового результату | Реальна YOLO-перевірка залишається відкладеною до фінальних ваг, як і до оформлення |
| /monitoring | Читання наявного списку джерел | Керування потоками, відеосітка, поточні події; дії disabled, є «Заплановано» |
| /events | Реальний список джерел для структури фільтра | Фільтрація подій, таблиця, бічна картка кадру/часів/фрагмента/оцінки; порожні значення й disabled save/export |
| /experiments | Чинний реєстр model_versions: архітектура, класи, SHA/шлях, доступність файла, пагінація | Порівняння, таблиця метрик і області графіків; без штучних кривих/метрик |
| /settings | Read-only GPU/queue/upload limit з існуючих API; явно позначені типові значення чинної форми аналізу | Глобальне редагування/збереження та часові правила; невідомі значення «—», Save disabled |

У макетах немає фіктивних подій, моделей, точності, активних потоків або повідомлень про збереження. Нових backend endpoints не створювали. Наявні Python/backend, ML-залежності, training-код, дані, конфігурація й процес навчання не змінювалися. GPU не використовували; перевірки браузера — CPU renderer із вимкненим hardware video decode.

## Фактично перевірено

TypeScript і production build пройшли. У Edge при масштабі 100%, device scale factor 1: **усі 6 маршрутів × 3 розміри** (1920×1080, 1366×768, 390×844), пряме відкриття та refresh, виділення поточного розділу, назад/вперед, розгортання/закриття mobile sidebar, Escape і повернення фокуса. Ширини:

| Viewport | Sidebar | Header | Вміст | Горизонтальний scroll документа |
| --- | ---: | ---: | ---: | --- |
| 1920×1080 | 240 px | 64 px | 1600 px | Немає |
| 1366×768 | 240 px | 64 px | 1062 px | Немає |
| 390×844 | Згорнутий | 64 px | 358 px | Немає |

На всіх звичайних сторінках немає console.error/pageerror. З реальним наявним API перевірені server health, порожні джерела/моделі/запуски, disabled start без моделі й живе WS-перепідключення. Усі скриншоти нижче — з цих реальних read-only сторінок, не з fixtures.

Окремо в ізольованому browser-context перехопленими відповідями API перевірені **frontend-контракти**, без записів у робочу БД: multipart/201/повідомлення/деталі/відео/seek; відмова перевищеного розміру до POST; помилка кодека; умовна пагінація; точні пороги й пристрій; 409 create без «фантомного» запуску; справжня для UI послідовність WS states; запит cancel без передчасного stopped; підтвердження stopped; completed/files/reload й відсутність implicit cancel. Тестові назви та дані існують лише всередині test harness, не в продукті або скриншотах. Реального YOLO чи worker в цих перевірках не запускали. Повні тести БД і ML не повторювали.

Доступність: поля всіх 6 сторінок мають labels/aria-label; keyboard skip-link, focus 3 px, native dialogs з Escape/поверненням фокуса. Виміряний контраст: основний текст/фон 13.57:1; другорядний/фон 4.75:1, /білий 5.14:1; основна кнопка 6.94:1; outline 3.92:1. Disabled controls є недоступними діями, не прихованими робочими можливостями.

Докази: [checks.json](checks.json), [accessibility.json](accessibility.json). Візуальні перевірки screenshot виконано локально через view_image. Знімки full-page, тому їхня висота може перевищувати висоту viewport через звичайний вертикальний scroll.

## Запуск і межі

Поточний frontend доступний на http://127.0.0.1:5173. Додати до адреси /sources, /analysis, /monitoring, /events, /experiments або /settings. Заходження на / переводить до /sources. При майбутньому статичному розгортанні потрібен звичайний SPA fallback до index.html; backend для цього етапу не змінювали.

Повторна frontend-перевірка (за вже запущених UI/API):

```powershell
Set-Location D:\FireVision
.\scripts\check-interface.ps1
```

Потрібні встановлений Edge/playwright-core і короткий технічний test clip у .tmp/analysis-test-* від попередніх перевірок. Harness не читає датасет/ваги, не запускає навчання і не робить робочих POST. Додані browser-assertions для старих smoke/analysis helper адаптовано до нової навігації; самі повні БД/ML набори не перезапускали.

Блокерів цього frontend-етапу немає. Моніторинг, events API/часові правила, experiment comparison та settings write API залишаються майбутніми backend-етапами. Фінальні ваги, їхня реєстрація та реальна YOLO end-to-end перевірка — попередньо відкладені роботи, не результат цього оформлення.
